# Shenzhen Functional Land-Use Workflow

This repository contains the notebook, scripts, and compact data package used to reproduce the Shenzhen functional land-use workflow for the manuscript.

## Repository Layout

- `UFS_2020_v2.ipynb` keeps the original notebook execution flow, with cleaned English section titles and updated script names.
- `code/` contains the scripts called by the notebook. Files are numbered in execution order.
- `data/` contains sampled raw POI files, compact intermediate products, model inputs, validation data, and figure/table inputs.
- `docs/script_name_mapping.csv` maps each renamed script back to its original source file.

## Data Policy

The original POI shapefiles are very large, so this package includes only the first 50 records from each raw POI shapefile under `data/poi_2020/`. These files are intended for checking schema, code execution, and preprocessing logic. Compact downstream grid products are included so later modeling and plotting steps can be inspected without redistributing the full raw POI collection.

Large model artifacts over normal GitHub limits were not copied. In particular, the large RF joblib files can be regenerated by running the training scripts. The model-validation plotting script skips RF variable-importance calculation when the RF artifact is absent, while retaining the tabular performance summaries already included in the repository.

The full cleaned POI GeoPackage is also omitted because it exceeds normal GitHub single-file limits. It can be regenerated from the sampled POI files for code checks, or from the full raw POI collection outside this compact repository.

The raw national TCULU rasters are not included. The extracted Shenzhen clips and validation products are included under `data/tculu_shenzhen/`. To rerun extraction from raw TCULU rasters, place `china_land_useYYYY.tif` files under `data/external/china_urban_landuse/`.

## How to Run

Create a geospatial Python environment with the packages listed in `requirements.txt`, then open `UFS_2020_v2.ipynb` from the repository root.

Some cells submit Google Earth Engine export tasks. These require Earth Engine authentication and the grid asset configured in the corresponding scripts. If you only want to inspect downstream code, use the included CSV feature tables in `data/GEE/shenzhen_features_2000_2020/`.

The notebook is designed to run from the repository root. All project paths in copied scripts have been rewritten to use repository-relative paths.

## Script Order

The scripts are named in notebook execution order:

1. `01_...` to `06_...`: POI inspection, cleaning, and grid scoring.
2. `07_...` to `11_...`: GEE feature/LST export and verification.
3. `12_...` to `15_...`: GAIA and TCULU processing/validation.
4. `16_...` to `20_...`: label fusion and model training/prediction.
5. `21_...` to `30_...`: area comparison, thermal analysis, and visualization.

## Notes for GitHub

This directory is currently below the per-file 100 MB limit after excluding the large RF model artifacts and full raw POI files. The total repository size is still substantial because geospatial data are included. For long-term archival, consider Git LFS, Zenodo, OSF, or another data repository for the `data/` directory.
